## Comparison candidates, not implementation conclusions

1. If ChatGPT artifact evidence identifies connection/session reuse, compare the verified lifetime and ownership boundaries above before proposing cross-turn reuse in Jarvis. A reusable socket and a reusable turn-routing token have different lifetimes.
2. If artifact evidence identifies render coalescing or lazy work, compare it with Jarvis's 50 ms native throttle, paged history and lazy Markdown. Static code cannot establish CPU cost, frame time or user-visible latency improvement.
3. Compare cache **routing keys**, actual **reported cached-token counts**, local **history/snapshot caches**, and retained **response chains** separately. A string named “cache” cannot establish a provider optimization.
4. Any transport/retry port must retain Jarvis's complete-result receipts, cancellation, storage error boundaries and protocol compatibility. Retry safety and `store` semantics are product contracts, not incidental performance details.

No source implementation was changed. No tests, benchmarks, native runs, provider traffic, commits, pushes or Dolt sync were performed. The listed tests were inspected as source contracts only. Actual performance benefits and parity with the ChatGPT binary remain unverified.
